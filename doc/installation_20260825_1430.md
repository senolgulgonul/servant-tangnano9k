# Installation and build guide

Building the Servant SoC for the Sipeed Tang Nano 9K with Gowin EDA.

## Prerequisites

- Gowin EDA (tested with V1.9.12). The free Education edition covers the
  GW1NR-9 with no license file.
- Git.
- openFPGALoader, or the Programmer bundled with Gowin EDA.

## Getting the sources

```
git clone --recursive https://github.com/senolgulgonul/servant-tangnano9k.git
```

`--recursive` matters: SERV itself is pulled in as a submodule under `serv/`.
If you cloned without it, run `git submodule update --init` afterwards.

## Creating the project

File > New > FPGA Design Project.

- Series: **GW1NR**
- Device: **GW1NR-9**
- Device Version: **C**
- Package: **QFN88P**
- Speed: **C6/I5**

The part number should read `GW1NR-LV9QN88PC6/I5`.

The device version matters. The chip on the Tang Nano 9K is the C revision;
leave the version unset and the bitstream still builds and still loads, but
the board does nothing and reports nothing.

## Adding the sources

Add Files, then select:

From `serv/rtl/`, all 16 files:

```
serv_aligner.v serv_alu.v serv_bufreg.v serv_bufreg2.v
serv_compdec.v serv_csr.v serv_ctrl.v serv_decode.v
serv_immdec.v serv_mem_if.v serv_rf_if.v serv_rf_ram.v
serv_rf_ram_if.v serv_rf_top.v serv_state.v serv_top.v
```

From `serv/servile/`, all 4 files:

```
servile.v servile_arbiter.v servile_mux.v servile_rf_mem_if.v
```

From `serv/servant/`, these 5 files only:

```
servant.v servant_ram.v servant_timer.v servant_gpio.v servant_mux.v
```

Do NOT add `serv_synth_wrapper.v` (a standalone synthesis wrapper, clashes
with the top), `servant_ram_quartus.sv` (Quartus-specific) or `serv_debug.v`.

From this repository:

```
servant/servant_tangnano9k.v
data/tangnano9k.cst
```

That is 27 files in total: 26 Verilog and one constraint file.

Set the top module under Project > Configuration > General:
`servant_tangnano9k`.

## Pointing at the memory image

Copy `serv/sw/blinky.hex` next to your project file, then edit the parameter
in `servant/servant_tangnano9k.v` to an absolute path with forward slashes:

```verilog
  #(parameter memfile = "C:/work/servant_tn9k/blinky.hex",
```

Do not skip this and do not use backslashes. GowinSynthesis runs from
`impl/gwsynthesis`, so a relative path will not resolve, and backslashes are
eaten as escape characters inside the Verilog string. Either way the failure
is silent: the RAM stays zeroed, the core executes nothing, and the LED never
lights. No error is reported.

Gowin ignores `$display`, so the confirmation that the image loaded is the
absence of an `EX3988 Cannot open file` warning in the synthesis log, not any
positive message.

## Build and program

Run Synthesize, then Place & Route. The bitstream lands in `impl/pnr/`.

Program with the bundled Programmer (SRAM Program for quick tests, embFlash
Erase, Program for persistence; the Verify variant is not supported on this
board), or:

```
openFPGALoader -b tangnano9k impl/pnr/<project>.fs        # SRAM, volatile
openFPGALoader -b tangnano9k -f impl/pnr/<project>.fs     # embedded flash
```

## Expected result

LED0 blinks at a comfortable rate.

## Pinout

| Signal | Pin | Note |
| --- | --- | --- |
| `i_clk` | 52 | 27 MHz oscillator |
| `i_rst_n` | 4 | Button S1, active low |
| `o_uart_tx` | 17 | To USB serial via the on-board BL702 |
| `o_led` | 10 | LED0, active low |

Only one LED is used because servant drives a single output bit. LED4 and
LED5 sit on pins 15 and 16 in Bank 3, which the on-chip PSRAM locks to 1.8 V;
constraining anything there as LVCMOS33 fails with CT1136. Pin 4 is in the
same bank, so its constraint carries no IO_TYPE.

## Running Zephyr

Point `memfile` at one of the prebuilt images in `serv/sw/` and set `memsize`
to match:

| Image | memsize |
| --- | --- |
| `zephyr_hello.hex` | 8192 |
| `zephyr_hello_mt.hex` | 16384 |
| `zephyr_sync.hex` | 16384 |
| `zephyr_phil.hex` | 16384 |

The core runs at the native 27 MHz and the UART is bitbanged, calibrated for
115200 baud at 32 MHz, so the actual line rate is 115200 * 27/32 = **97200
baud**. Set your terminal accordingly; PuTTY and Tabby both accept arbitrary
rates.

The console is transmit only. Servant's only port besides clock and reset is
a single output bit, so there is no shell and nothing to type.

## Troubleshooting

LED dark after programming, in order of likelihood:

1. No `EX3988` warning check: the memory image did not load. Fix the
   `memfile` path.
2. Device Version not set to C.
3. The `.fs` was built but the wrong file was programmed.

`CT1136 Bank 3 vccio(1.8) is locked`: a constraint forces LVCMOS33 on a pin
in the PSRAM bank (4, 15 or 16). Remove the `IO_TYPE` from that pin.
